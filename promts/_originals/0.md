# Ratify

Native CRM + AI sales optimization platform. Single-enterprise deployment
target: one t3.xlarge EC2 instance, Docker Compose, ~10k records/month.

## Architecture (locked — do not propose alternatives without flagging)

- Go modular monolith for CRM, sequencing, CPQ. Python for ML, agents, ASR.
- PostgreSQL 17 with **RLS**. Tenant binding is transaction-scoped via
  `set_tenant(uuid)` which uses `set_config('app.tenant_id', $1, true)`.
  NEVER use `SET SESSION app.tenant_id` — it leaks across pooled connections.
- All DB access goes through `internal/db.TenantTx.WithTenant`. Handlers
  must never call pgxpool directly. The API refuses to boot as superuser
  or as `app_migrator` (see `AssertNotPrivileged`).
- Apache Kafka 4.x KRaft (single broker, RF=1, heap capped 1 GB). NOT Redpanda
  (BSL license conflict). Transactional producers + outbox pattern for any
  paid side effect (email send, SMS, enrichment call).
- FerrisKey for OIDC (pinned version, default admin/admin overridden). NOT
  Keycloak. Dev mode: X-Tenant-Id header when OIDC_ISSUER is empty AND
  ENV != production.
- Temporal for durable outer workflow; LangGraph for inner cognitive graph.
  No parallel checkpointer — durability comes from Temporal.
- Decision gate is a SEPARATE Go service. Every AI write action passes
  through it. Records are append-only and immutable.
- Postal MTA for email. Synchronous suppression list check on the send path.
  Warmup enforced (start 100-200/day, double every 2-3 days over 4-6 weeks).
  DMARC p=none → quarantine → reject. Never send bulk above warmup cap.
- pgvector 0.8+ with iterative scans enabled. Escalation trigger to Qdrant:
  filtered recall misses target under tenant-scoped queries OR HNSW memory
  pushes instance into swap. NOT a fixed vector count.

## Non-negotiables

1. **Tenant isolation** — RLS is the safety net, not the primary gate.
   Every query must have tenant context. Missing context = error, not
   "see everything".
2. **Decision gate** — no agent writes to CRM or sends outreach without
   passing the gate. No exceptions, even in tests.
3. **Outbox pattern** — paid side effects go through outbox. If it can
   cost money or send an email, it needs the outbox.
4. **Resource limits** — every Compose service has explicit mem_limit and
   cpus. These are load-bearing on single-instance deployment.
5. **Fail closed** — missing tenant, missing consent, missing suppression
   check, missing decision record: all fail the request, not degrade.

## Testing discipline

- Every sprint ends with a passing test suite.
- The tenant isolation test (`tests/tenant_isolation_test.go`) is a
  REQUIRED gate. It must pass before any business logic.
- Cross-tenant attempts are tested, not assumed away.
- AI write actions are tested via the decision gate, never mocked past it.

## Project layout

    cmd/api/            Go API entrypoint
    cmd/relay/          Outbox relay (Phase 0.2)
    cmd/decisiongate/   Decision gate service (Phase 3)
    internal/           Go modules (compiler enforces boundaries)
    migrations/         SQL migrations (golang-migrate format)
    tests/              Integration tests, RLS gate
    web/                Next.js app (Phase 1.3)
    agents/             Python agent runtime (Phase 3)
    deploy/             Docker Compose, Dockerfiles, initdb

## Deployment target

Single t3.xlarge (4 vCPU, 16 GB). Docker Compose. Explicit resource limits
sum to ~12.7 GB, leaving headroom. Do not add services without trimming
elsewhere. Kafka capped at 1 GB heap.

## When in doubt

Ask. Do not invent architecture. If a task seems to require violating a
non-negotiable above, flag it before proceeding.
